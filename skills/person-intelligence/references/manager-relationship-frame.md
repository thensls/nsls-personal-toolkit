# Operating user → their manager (upward) frame

This instruction block is appended to the synthesizer's system prompt **only when** `relationship_type == "manager"` — i.e., when synthesizing a profile of the operating user's own boss. The reference example is Kevin Prentiss's profile of Gary Tuerack, updated 2026-05-16 with the "Respect, Protect, Resent" stance pattern.

The user is the report here, not the manager. The coaching artifacts are aimed at the user's own behavior in the relationship, not at the manager.

---

## Two new sections for upward profiles

Add these sections, in this order, between the standard sections and `## Coaching Goals`:

### Section 1: `## My Stance: [emotion], [emotion], [emotion]`

The user's emotional frame for the relationship. Name 2-4 dominant emotions in the headline; develop each one in 1-2 short paragraphs below. **The Kevin → Gary "Respect, Protect, Resent" pattern (added to Gary's profile 2026-05-16) is the structural reference, not the literal content** — each user has different emotions toward their own manager.

Look in the source data for:
- What emotions does the user repeatedly express about this person?
- Where is there cognitive dissonance (positive language masking unresolved tension)?
- What does the user *defend* about this person? What does the user *protect them from*? What does the user resent?
- What emotional labor does the user perform in this relationship?

The headline names 2-4 emotions explicitly. The body develops each one with evidence and what it actually looks like in practice. End with a paragraph titled **"How I feel about the relationship"** that synthesizes — loyalty? burden? hope? frustration? Be honest. This section is private.

Follow with a **"### The arc"** subsection that describes how the relationship has evolved across the data span. Use period headers ("Early phase", "Middle phase", "Recent phase", "Ongoing") with a sentence or two each. This gives the user a temporal view of the relationship.

Follow with a **"### How it shows up day to day"** subsection — concrete bulleted patterns of behavior on both sides.

End with a **"### Guardrail"** subsection if the data suggests the user is vulnerable to a specific failure mode in this relationship (e.g., resentment accumulating, conflict avoidance, deference under stress). Name the discipline the user should practice. Keep it actionable.

### Section 2: `## How I Can Work More Effectively with [Name]`

*The user's coaching of themselves in this relationship.* Specific behaviors the user is practicing to manage upward better. Think of this as the inverse of the manager-coaching frame's "How I Work" section — but written by the report about the manager, for the report's own use.

Use these four default subsections (omit any that aren't supported by data):

#### `### What they respond best to`
What format, framing, channel, timing tends to land well with this manager. Specific. *"Three short bullets with the recommended decision, not a five-paragraph context dump."* Cite evidence.

#### `### What surprises or destabilizes them`
What patterns the user has noticed put this manager into a defensive or reactive posture — the things to anticipate and pre-manage. *"Public disagreement in front of the SLT triggers a protective reflex; raise the same point privately first."*

#### `### Where I have latitude`
Areas where this manager has explicitly or implicitly granted the user authority to decide and execute without needing approval. Naming this prevents the user from over-checking-in.

#### `### Where I need to bring them in early`
Areas where the manager wants visibility before decisions are finalized — even when their input isn't strictly required. Often the soft contract that prevents friction.

### Coaching goal updates

After the two sections above, evaluate active coaching goals (if any) in the profile's `## Coaching Goals` section. Look at recent meeting summaries for evidence of progress, regression, or new patterns that warrant a new goal. Surface proposed updates **in the digest, not in the profile itself.** The user reviews and accepts/edits/rejects.

---

## Preserve human-authored content

If the existing profile already has a `## My Stance` section (e.g., Kevin's Gary profile, updated 2026-05-16), **read it carefully and propose updates rather than rewriting from scratch.** The existing emotions named, the existing guardrail, the existing arc framing — these are the user's curated content. If the recent data suggests an adjustment, surface it as a proposed change in the digest, not as a silent overwrite.

If a `## Guardrail` exists and the recent data shows the discipline being practiced (or violated), note that in the digest. Don't invent new guardrails without strong evidence.

---

## Voice

- First person ("I", "my") — this is the user's own coaching of themselves
- Honest, specific, evidence-cited
- Plain language, declarative headlines
- Short sentences. Numbers and quotes over adjectives.
- The Kevin/Gary 2026-05-16 update is the voice reference — terse, direct, names uncomfortable truths
