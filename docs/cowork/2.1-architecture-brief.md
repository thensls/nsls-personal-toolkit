# Cowork Dashboard 2.1 — Architecture Brief (for review)

Context: building Phase 2.1 of a Claude Desktop ("cowork") React artifact that renders the
NSLS personal-productivity daily ritual. The artifact is a SINGLE self-contained `.jsx` file
that cowork renders inline in a chat — no build step, no npm, no module bundler, nothing
cowork can't resolve at render time. Tailwind is available in the artifact runtime.

## Verified runtime facts (Phase 0, real cowork session)

- The ONLY artifact→Claude hand-back channel is a global `sendPrompt(text)` — it posts `text`
  into the chat AS IF the user typed it. There is NO silent callback. `window.claude.complete()`
  does not exist in cowork. `postMessage` to parent posts but never reaches the model.
- Therefore every save is a real chat turn (a visible user message + Claude's write turn).
  Saves must be explicit and batched; per-tap autosave is forbidden (token flood).
- File access: write/read frictionless; DELETE is permission-gated. So the vault write-back is
  whole-file replace, never delete-then-write.

## The shared contract (already shipped, both surfaces honor it)

- Daily note carries `status: planning | active | closed` frontmatter — the single signal that
  picks the mode. Never infer mode from which sections exist.
- Python `_detect_day_state` maps status→mode: closed→results; active→command (or coach-evening
  if an `## Insight Reflection` heading is present); planning→coach-morning; absent→legacy
  inference. The JS artifact MUST agree with this exactly.
- Streak rule is canonical in Python (`streak.py`); a JS display copy (`streak.js`) exists with a
  parity test.

## 2.1 scope (this phase)

A "thin shell + 4 stubbed modes": prove the whole frame end-to-end with a hardcoded sample
state; flesh out each mode in later phases (2.2–2.6).

## Proposed component structure (one .jsx file)

```
cowork-dashboard.jsx
├─ STATE CONTRACT      (the JSON shape Claude seeds + the artifact emits on save)
├─ pure helpers (no React, unit-testable in isolation via Node):
│   ├─ deriveMode(status, phase) -> 'coach-morning'|'command'|'coach-evening'|'results'
│   │     (mirrors Python _detect_day_state EXACTLY)
│   ├─ serializeForSave(state)   -> compact payload object for sendPrompt
│   └─ streak display helpers    (ported from streak.js, parity-tested vs streak.py)
├─ presentational components: <Disc> <TaskRow> <Panel> <HabitChip>  (brand-styled, Tailwind)
├─ 4 mode components: <MorningCoachCards> <CommandCenter> <EveningCoachCards> <Results>
│     (stubbed in 2.1 — minimal placeholder content)
└─ <CoworkDashboard state={SAMPLE}> root: routes on status via deriveMode, holds edit state,
      owns the Save action
```

## Data flow

1. IN: Claude parses the daily note in Python, hands the artifact ONE JSON state blob as a prop.
   In 2.1 this is a hardcoded realistic SAMPLE constant (skill wiring is Phase 3).
2. HOLD: root copies the blob into React state; all edits (ring taps for 0/25/50/75/100 progress,
   text edits, habit ticks, disposition toggles) are held LOCALLY. No writes during editing.
   Top-3 slots are POSITIONAL — never compact the array (a prior CLI bug compacted empty slots and
   jumped typed values between slots; we must not repeat it).
3. OUT: on explicit Save, serializeForSave(state) builds a payload and the artifact calls
   sendPrompt("SAVE_DAY " + JSON.stringify(payload)). Claude parses that message and writes the
   whole note back (whole-file replace, merging into sections it didn't touch — must not clobber
   close-day-only sections).

## Mode routing

deriveMode(state.status, state.phase). status is authoritative; phase ∈ planning|active|closing
carries entry-context for banners (e.g. the "type done to close" line in the closing pass).

## Testing approach

Pure helpers (deriveMode, serializeForSave, streak math) are framework-free and unit-tested with
Node (the repo already shells Node from pytest for the streak parity test). React components are
presentational and verified by eyeball in a real cowork session. No React test runner / jsdom /
vitest is added (cowork doesn't use a build output anyway).

## Open questions for the reviewer

1. Is "one big .jsx file with internal sections" the right call for an artifact that can't import
   modules, or is there a cleaner way to keep the pure helpers testable while still shipping one file?
2. Is the SAVE_DAY-via-sendPrompt design robust? Failure modes: user edits the artifact, navigates
   away without saving (state lost — acceptable?); double-save; a save message that's malformed;
   Claude mis-parsing the JSON out of a chat message.
3. deriveMode must match Python _detect_day_state. Is duplicating that logic in JS the right move,
   or should the artifact be handed the already-resolved mode by Claude (one less place to drift)?
4. Any risk in the whole-file-replace-on-save model when the same note could be touched by the CLI
   companion concurrently? (CLI is last-writer-wins; cowork is a separate session.)
5. Anything about holding all state in React for a long-lived daily session (open in the morning,
   tick through the day, close at night) that's fragile — given the artifact may be re-rendered or
   the chat scrolled away?
